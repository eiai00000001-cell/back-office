- 実装フェーズ(developer)・レビューフェーズ(reviewer)は完了済みで、reviewer検証によりレビュー指摘のうち重大度「高」2件・「中」4件は全て対応済みであることが確認されている(`docs/03_develop/レビュー結果報告書.md`4.1〜4.2章)。本書では、これらの指摘に対応する詳細設計項目についてtester自身も実機再検証し、参照のみに留めず重複確認する(README・レビュー結果報告書に記載済みの既知の指摘は、実際に解消されているかを実機確認した上で結果を記録する)。

## 3. テスト観点

| # | 観点 | 定義 |
|---|---|---|
| 1 | 機能テスト | 詳細設計書の画面詳細設計・処理フロー・API/インターフェース設計どおりに動作するか(機能ID単位) |
| 2 | 異常系・入力値検証 | エラーハンドリング設計(詳細設計書8章)どおりに異常系が処理されるか |
| 3 | データ整合性 | DB詳細設計(詳細設計書6章)どおりにデータが登録・更新・参照されるか |
| 4 | 回帰確認 | フォローアップ時、既存の合格項目が新規修正で崩れていないか(初版では該当なし) |
| 5 | 機能横断・結合確認 | 複数機能にまたがる画面遷移・データの受け渡し等、単体テスト・機能単位レビューでは見えない不整合がないか(F-03→F-04→F-01→F-05の一連の業務フロー、ホーム画面のサマリー算出とF-05判定ロジックの整合等) |

### 3.1 機能ID単位の適用方針

- F-01〜F-06および共通機能それぞれについて、観点1(機能テスト)・観点2(異常系)を基本の適用対象とする。
- F-01・F-02・F-03の金額計算はDB保存値の検算(観点3)を必須とする。
- F-04(見積→請求変換)・F-05(入金・売掛金管理)・F-06(ホーム画面サマリー)は、他機能のデータに依存して算出される派生値が多いため、観点5(結合確認)を重点的に適用する。
- 起動.app/終了.appは、単体スクリプト実行(developer済み確認)に加えて実際の`.app`バンドル起動(観点1・5)を重点的に確認する。

## 4. テスト方針・実施方法

### 4.1 実施方法の区分

| 区分 | 内容 |
|---|---|
| 実機確認(バックエンドAPI) | 本番相当構成(`npm run build`→`uvicorn app.main:app`)でサーバーを実際に起動し、`curl`によるHTTPリクエストで全APIエンドポイントを実行し、レスポンス内容(ステータスコード・JSON本体)およびSQLite上のデータを検証する。 |
| 実機確認(.app起動・終了) | `dist/起動.app`・`dist/終了.app`をmacOSの`open`コマンドで実際に起動し(Finderでのダブルクリックと同一のLaunch Services経由の起動)、実ブラウザのHTTPアクセスログ・プロセス起動状況・PIDファイル・`osascript`通知ダイアログの実際の表示有無を確認する。 |
| 実機確認(SPA読み込み) | 実ブラウザ(Google Chrome)で`http://127.0.0.1:8000/`にアクセスし、SPAのHTMLアセット・JSバンドル・APIコールがサーバーログ上で正常に発生することを確認する。ヘッドレスブラウザ自動操作ツール(Playwright等)は本環境に未導入のため、画面要素クリック単位のE2E自動操作・スクリーンショットによる目視確認までは実施していない(要確認事項参照)。 |
| 静的確認 | フロントエンド実装コード(`frontend/src/pages/`・`components/`)を詳細設計書3章の画面詳細設計・mockups(SC-01〜SC-11)と突き合わせ、画面遷移・入力項目・バリデーション・表示ロジックの実装内容を確認する。UI操作結果そのものの実機確認ができない項目(ボタンクリックによる画面遷移の見た目等)を補完する位置づけとし、単独では合格根拠としない。 |
| 参照確認 | README.md「5. テスト実行結果」(pytest 127件・Vitest 26件)、レビュー結果報告書.md 4章の指摘対応状況を参照し、重複再実行はしない。 |

### 4.2 合否判定基準

- 期待結果(テストケース.mdに記載)と実施結果が一致した場合を「合格」とする。
- 詳細設計書・機能仕様書に明記された仕様との不一致、または実行時エラー・データ不整合が確認された場合を「不合格」とし、再現手順・実際の結果を記録する。
- README.md「6. 詳細設計書との差異」に記載済みの差異は仕様確定事項として扱い、原則不合格としない。ただしその差異どおりに実際に動作しているかは実機確認する。
- テスト実施中に、詳細設計書とmockupsとの間、または詳細設計書内の章同士の間で軽微な記載の不整合が見つかった場合(実装への影響がないもの)は「要確認事項」として記録し、不合格扱いとはしない。
- 実機確認の手段がない項目(ヘッドレスブラウザ非導入によるピクセル単位確認等)は「未実施」とし、代替として実施した静的確認・参照確認の内容を明記する。
