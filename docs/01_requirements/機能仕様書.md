## 4. 機能別詳細仕様

### F-01 請求書発行

#### 目的

EIAI TECが取引先への請求書を作成し、金額計算を誤りなく行った上でPDFとして出力できるようにする(要件定義書6.1)。

#### 入力

- 取引先(請求先): 取引先マスタ(5.1参照)から選択、または新規登録。
- 発行日、支払期限
- 請求書番号: 自動採番(手動編集は不可とする。採番ルールは「発行年+連番」とする)
- 品目明細(1件以上): 品目名、数量、単価、税区分(標準10%/非課税/不課税から選択。軽減税率8%は扱わない。要件定義書10.1★3)
- 備考(任意)
- 発行者情報(EIAI TECの氏名・屋号・住所・連絡先、適格請求書発行事業者登録番号): システム設定として別途登録し、請求書作成時は登録済み情報を参照する想定。登録番号欄はレイアウト上用意するが、記載は必須としない(インボイス制度への対応方針自体は未定。要件定義書10.1★1)

#### 処理内容

1. 品目明細ごとに「数量×単価」で金額を算出する。
2. 税区分ごとに小計を集計し、税区分ごとの消費税額を計算する(消費税額の端数処理は切り捨てとする。要件定義書10.1★2)。
3. 小計・消費税額・合計金額を自動計算し、画面に表示する。
4. 保存時に請求書番号を自動採番する。
5. 請求書データをもとにPDFを生成し、画面から保存・印刷できるようにする。
6. インボイス制度に対応するレイアウト(登録番号欄、税率ごとの区分記載、適用税率、税率ごとの消費税額)を帳票フォーマットに含める。登録番号欄は記載必須項目とはしない(要件定義書10.1★1)。

#### 出力

- 請求書一覧画面(請求書番号・取引先・発行日・支払期限・合計金額・入金状況(F-05と連携)を表示)
- 請求書詳細画面
- 請求書PDF

#### 例外・エラー時の扱い

- 品目明細が0件の場合は保存できず、エラーメッセージを表示する。
- 数量・単価に0以下または数値以外が入力された場合は保存できず、エラーメッセージを表示する。
- 取引先が未選択の場合は保存できず、エラーメッセージを表示する。
- 発行済みの請求書番号は変更できない(再発行が必要な場合は新規作成とする)。

#### イテレーション3追記(F-08連携。10.3★19参照、確認後に確定)

- 入力に「案件」(任意。F-08の案件から選択)を追加する。未選択でも保存できる。既存の請求書は「案件なし」のまま利用でき、後から案件を選んで紐付けられる。
- 請求書一覧に案件名を表示できる(仮置き)。

### F-02 経費管理

#### 目的

EIAI TECが日々発生する経費を記録し、勘定科目別・期間別に集計・確認できるようにする(要件定義書6.2)。

#### 入力

- 発生日
- 勘定科目: 下記の標準科目リスト(青色申告向け)から選択(要件定義書10.1★4で確定)
  - 旅費交通費、通信費、消耗品費、水道光熱費、地代家賃、外注工賃、接待交際費、会議費、新聞図書費、支払手数料、租税公課、雑費、その他(自由入力)
- 金額
- 税区分(標準10%/非課税/不課税/対象外から選択。軽減税率8%は扱わない。要件定義書10.1★3)
- 支払先(任意)
- 支払方法(現金・クレジットカード・銀行振込・その他から選択。この選択肢はEIAI TECへのヒアリング対象外の実装レベルの初期案であり、必要に応じて設計フェーズで見直してよい)
- メモ(任意)
- 領収書ファイル(画像・PDF、任意添付。初回スコープに正式に含む。要件定義書10.1★5)

#### 処理内容

1. 入力内容をもとに経費データを保存する。
2. 経費一覧を発生日の新しい順に表示する。
3. 勘定科目・支払方法・期間による絞り込み検索ができる。
4. 勘定科目別・期間(月単位)別に金額を集計し、一覧表示できる。
5. 領収書ファイルが添付されている場合、一覧・詳細画面からファイルを確認できる。

#### 出力

- 経費一覧画面
- 勘定科目別・期間別集計結果画面

#### 例外・エラー時の扱い

- 金額が0以下または数値以外の場合は保存できず、エラーメッセージを表示する。
- 勘定科目・発生日が未入力の場合は保存できず、エラーメッセージを表示する。
- 対応していない形式のファイルが添付された場合はエラーメッセージを表示し、添付を受け付けない(対応形式は設計フェーズで確定)。

#### イテレーション3追記(仮置き。10.3★20参照、確認後に確定)

- 経費を案件に紐付けるかは未確定である。紐付ける場合は、入力に「案件」(任意)を追加し、既存の経費は「案件なし」のまま利用できる。この追記は案件別採算(F-11)のためであり、F-07の集計には影響しない。

### F-03 見積書作成

#### 目的

EIAI TECが取引先への見積書を作成し、金額計算を誤りなく行った上でPDFとして出力できるようにする(要件定義書6.3)。

#### 入力

- 取引先(見積先): 取引先マスタ(5.1参照)から選択、または新規登録。
- 発行日、有効期限
- 見積書番号: 自動採番(発行年+連番とする)
- 品目明細(1件以上): 品目名、数量、単価、税区分
- 備考(任意)
- ステータス: 「作成中」「確定」の2区分とする(提出済み・承認・却下等の詳細なワークフローは持たない。要件定義書10.1★7で確定)

#### 処理内容

1. F-01と同様のロジックで、品目明細から小計・税区分ごとの消費税額・合計金額を自動計算する。
2. 保存時に見積書番号を自動採番する。
3. 見積書データをもとにPDFを生成し、画面から保存・印刷できるようにする。

#### 出力

- 見積書一覧画面(見積書番号・取引先・発行日・有効期限・合計金額・ステータスを表示)
- 見積書詳細画面
- 見積書PDF

#### 例外・エラー時の扱い

- 品目明細が0件の場合、数量・単価が不正な値の場合、取引先未選択の場合は、F-01と同様に保存できずエラーメッセージを表示する。

#### イテレーション3追記(F-08連携。10.3★19参照、確認後に確定)

- 入力に「案件」(任意。F-08の案件から選択)を追加する。既存の見積書は「案件なし」のまま利用でき、後から紐付けられる。

### F-04 見積→請求の自動変換

#### 目的

確定済みの見積書の内容を請求書へ引き継ぎ、同じ内容の二重入力をなくす(要件定義書6.4)。

#### 入力

- 変換元とする見積書(見積書一覧・詳細画面から選択)

#### 処理内容

1. 選択した見積書の取引先情報・品目明細(品目名・数量・単価・税区分)を複製し、新規の請求書データを作成する。
2. 新規請求書には新たな請求書番号を自動採番する。
3. 発行日・支払期限は変換時点では未設定とし、ユーザーが入力・編集する。
4. 変換後の請求書は、通常の請求書編集画面(F-01)と同じ画面で内容を編集できる。
5. 変換元の見積書と変換後の請求書は、変換後は互いに独立したデータとして扱う(一方を編集しても他方には反映されない)。請求書データには変換元の見積書番号を参照情報として保持し、どの見積書から変換されたかを画面上で確認できるようにする。
6. 1件の見積書から変換できる請求書は1件とする(1対1。要件定義書10.1★8で確定)。部分請求・分割請求への対応は本イテレーションでは扱わない。ただし将来イテレーションでの拡張要望を踏まえ、請求書側から見積書を一方向に参照する構造とし、見積書側に「1対1」を固定する制約は持たせない設計とする(要件定義書7章参照)。将来イテレーションで分割請求・部分請求(1見積書から複数請求書)への拡張を行う際の具体的なデータモデル変更は、当該イテレーションの設計フェーズで検討する。

#### 出力

- 変換によって新規作成された請求書(編集可能な状態の請求書詳細画面)

#### 例外・エラー時の扱い

- 見積書のステータスが「作成中」であっても変換は可能とする(要件定義書10.1★7)。
- 変換元見積書がすでに他の請求書に変換済みの場合は、1対1の対応関係(要件定義書10.1★8)を維持するため、再変換を不可とし、確認ダイアログを表示する。

#### イテレーション3追記(F-08連携。10.3★19参照、確認後に確定)

- 変換元の見積書に案件が紐付いている場合、作成される請求書にも同じ案件を引き継ぐ(変換後に請求書側で変更・解除できる)。案件が未設定の場合は、請求書も案件なしとなる。

### F-05 入金・売掛金管理

#### 目的

発行済みの請求書について入金状況を記録し、売掛金(未回収金額)と支払期限超過の状況を把握できるようにする(要件定義書6.5)。

#### 入力

- 対象請求書(請求書一覧・詳細画面から選択)
- 入金日、入金額、備考(任意)

#### 処理内容

1. 請求書ごとに、記録済みの入金額の合計と請求金額を比較し、入金ステータスを自動判定する。
   - 入金額合計が0円: 「未入金」
   - 入金額合計が請求金額未満: 「一部入金」
   - 入金額合計が請求金額以上: 「入金済み」
2. 支払期限を過ぎても「未入金」または「一部入金」のままの請求書を「支払期限超過」として判定する。
3. 請求書一覧・売掛金一覧画面において、「支払期限超過」の請求書を強調表示(色分け等)する。
4. ホーム画面(F-06)に、未入金件数・支払期限超過件数のサマリーを表示する。
5. アラートは画面表示によるものに限定し、メール送信・デスクトップ通知等のプッシュ型通知は行わない(要件定義書10.1★6で確定)。

#### 出力

- 売掛金一覧画面(取引先・請求書番号・請求金額・入金済み金額・入金ステータス・支払期限超過有無を表示)
- 入金記録一覧(請求書ごと)

#### 例外・エラー時の扱い

- 入金額が0以下または数値以外の場合は保存できず、エラーメッセージを表示する。
- 入金額合計が請求金額を超過する入力を行った場合は、確認メッセージを表示した上で登録可否をユーザーに委ねる(過入金・一部返金等のケースを想定)。

### F-06 ホーム画面・共通UI

#### 目的

EIAI TECがシステム起動後にF-01〜F-05の各機能へ迷わず移動できるようにし、業務上把握しておきたい簡易な状況を一目で確認できるようにする(要件定義書6.6)。

#### 入力

- なし(表示専用画面)

#### 処理内容

1. F-01(請求書発行)・F-02(経費管理)・F-03(見積書作成)・F-05(入金・売掛金管理)・F-07(財務ダッシュボード、イテレーション2で追加)への導線をメニューまたはカード形式で表示する。F-04(見積→請求の自動変換)は独立した導線ではなく、見積書詳細画面(F-03)からの操作導線として提供する。
2. 未入金件数、支払期限超過件数など、F-05から取得した簡易なサマリー情報を表示する。
3. ホーム画面自体では詳細な集計・グラフ表示は行わない。詳細な集計・グラフ表示は財務ダッシュボード(F-07、イテレーション2で追加)で提供する。

#### 出力

- ホーム画面

#### 例外・エラー時の扱い

- サマリー情報の取得に失敗した場合は、該当箇所にエラー表示を行い、他の導線メニューの表示・操作には影響させない。

#### イテレーション3追記(要件定義書6.6。10.3★21参照、確認後に確定)

- 導線にF-08(案件・プロジェクト管理)、F-09(通知一覧・期限登録)、F-10(レポート出力)、F-11(経営管理)を追加する。
- 通知エリアを追加し、F-09の未確認の通知件数と、期限が近い・超過している主な通知(件数は仮置きで上位5件。設計で確定)を表示する。既存の未入金件数・支払期限超過件数(F-05)の表示は変更しない。
- 通知の取得に失敗した場合は、通知エリアのみエラー表示とし、他の導線・サマリーには影響させない。

### F-07 財務ダッシュボード(イテレーション2)

#### 目的

EIAI TECが、イテレーション1で蓄積した請求書発行(F-01)・経費管理(F-02)・見積書作成(F-03)・見積→請求の自動変換(F-04)・入金/売掛金管理(F-05)の各データを月次で集計・可視化し、日々の事務作業だけでなく経営状況の把握・振り返りにも活用できるようにする(要件定義書6.7)。

#### 入力

- 本機能自体はデータの新規入力・編集を行わない、表示専用画面である(要件定義書6.7、5.2)。
- 表示対象期間の絞り込み操作は設けない。表示対象期間は常に「現在月を含む直近12ヶ月」に固定する(要件定義書10.2★13で確定)。
- 集計対象データは、F-01〜F-05で登録済みの以下の既存データを参照する(新規テーブルは持たない。5.7参照)。
  - 請求書データ(5.2)、請求書明細(5.3)
  - 見積書データ・見積書明細(5.4)
  - 経費データ(5.5)
  - 入金記録データ(5.6)

#### 処理内容

1. 売上・入金状況の集計: 直近12ヶ月について、月ごとに、発行済み請求書の合計金額(売上)と、入金記録(F-05)の入金額合計(入金)を集計し、折れ線グラフまたは棒グラフで推移を表示する。
2. 経費の集計: 直近12ヶ月について、月ごと・勘定科目ごとに経費金額(F-02)を集計する。月次推移は折れ線グラフまたは棒グラフ、勘定科目別の内訳は円グラフまたは棒グラフで表示する。勘定科目区分は経費管理(F-02)で定義済みの標準科目リスト(要件定義書10.1★4)をそのまま集計軸として使用し、財務ダッシュボード独自の区分は設けない(要件定義書10.2★15で確定)。
3. 損益(収支)の集計: 直近12ヶ月について、月ごとに「売上-経費」を算出し、折れ線グラフまたは棒グラフで推移を表示する。計上基準は発生主義とし、売上は請求書の発行日、経費は経費の発生日を基準として、該当する月へ計上する(入金日・支払日は計上基準に用いない。要件定義書10.2★14で確定)。
4. 見積状況の集計: 直近12ヶ月について、月ごとの見積作成件数・見積金額合計を折れ線グラフまたは棒グラフで集計・表示する。また、見積成約率を「見積→請求の自動変換(F-04)による変換件数 ÷ 見積作成件数」で算出する(要件定義書6.7)。
5. 上記1〜4のグラフ・表は、折れ線グラフ・棒グラフを中心とした一般的な構成とする(月次推移は折れ線グラフまたは棒グラフ、勘定科目別経費などの内訳は円グラフまたは棒グラフ)。具体的な画面レイアウト(配置・配色等)は設計フェーズ(architecture/designer)で具体化する(要件定義書10.2★12で確定)。
6. 直近12ヶ月のうち、実績(データ)が存在しない月についても、該当月を0円・0件として集計結果に含め、期間全体(12ヶ月分)の推移が連続して確認できるようにする(要件定義書10.2★16で確定)。
7. 各集計処理はF-01〜F-05のデータを読み取るのみで、書き込み・更新は行わない(要件定義書5.2)。

#### 出力

- 財務ダッシュボード画面(売上・入金状況/経費/損益/見積状況の4区画で構成する見込み。各区画は月次推移を折れ線グラフまたは棒グラフ、内訳(勘定科目別経費など)を円グラフまたは棒グラフで表示する。対象期間は直近12ヶ月固定で、期間絞り込みのUIは設けない。具体的な画面構成・配置は設計フェーズ(architecture/designer)で確定する)

#### 例外・エラー時の扱い

- 直近12ヶ月のうち、実績がない月は0円・0件として表示する(空欄表示・非表示にはしない。要件定義書10.2★16で確定)。
- 参照元データ(F-01〜F-05)の取得に失敗した場合は、該当する区画にエラー表示を行い、他の区画の表示には影響させない(F-06の例外時の扱いに準じる)。

### F-08 案件・プロジェクト管理(イテレーション3・段階1)

本機能の項目・ステータス・紐付け方法は要件定義書10.3★19・★20の確認前であり、以下は仮置きである(確認後に確定)。

#### 目的

EIAI TECが案件ごとの進捗・納期を把握し、案件に関連する見積書・請求書の状況をまとめて確認できるようにする(要件定義書6.8)。

#### 入力

- 案件の登録・編集: 案件名(必須)、取引先(任意。取引先マスタ5.1から選択)、進捗ステータス(未着手/進行中/確認待ち/完了。既定は未着手)、納期(任意)、概要メモ(任意)。
- 見積書・請求書の紐付け: 見積書(F-03)・請求書(F-01)の入力画面、または案件詳細画面から案件を選ぶ(任意)。
- カンバン上でのカード(案件)の列間移動によるステータス変更。

#### 処理内容

1. 案件の一覧を表示する(案件名・取引先・ステータス・納期・紐付け件数)。ステータスや取引先で絞り込める。
2. 簡易カンバン: ステータスごとの列に案件をカードで表示する。カードを別の列へ移動するとステータスが変更される。納期が過ぎた(完了以外の)案件、および納期が近い案件は、カード上で分かるように表示する。
3. 案件詳細で、紐付いた見積書・請求書の一覧と、件数・金額合計・入金状況(F-05)を表示する。
4. 請求書・見積書は複数を1案件に紐付けられる。1件の請求書・見積書が紐付けられる案件は1つとする。紐付けの追加・変更・解除ができる。
5. F-04で変換された請求書には、変換元見積書の案件を引き継ぐ。
6. 案件を削除する場合、紐付いた見積書・請求書は削除せず「案件なし」に戻す(削除前に確認メッセージを表示する)。
7. 既存の請求書・見積書は変更しない。紐付けは本人が任意に行う。

#### 出力

- 案件一覧画面、案件カンバン画面、案件詳細画面(紐付いた請求・見積の状況を含む)

#### 例外・エラー時の扱い

- 案件名が未入力の場合は保存できず、エラーメッセージを表示する。
- 納期が未設定の案件は、納期関連の表示・通知(F-09)の対象外とする。
- 完了済みの案件に請求書・見積書を紐付けようとした場合も、警告なく可能とする(仮置き。請求が完了後に発生することを想定)。

### F-09 リマインダー/通知(イテレーション3・段階2)

通知の対象・手段・タイミング・期限の登録方法は要件定義書10.3★21・★22の確認前であり、以下は仮置きである(確認後に確定)。

#### 目的

支払期限・納期・確定申告期限・契約更新日などの期限をEIAI TECが見落とさないよう、アプリ内で通知として確認できるようにする(要件定義書6.9)。

#### 入力

- 手動登録する期限: 名称(必須)、期限日(必須)、種別(確定申告/契約更新/その他)、メモ(任意)、毎年繰り返す(はい/いいえ)。
- 通知の「確認済み」操作。
- 通知の表示開始日数(期限の何日前から表示するか。仮置き既定は7日。設定変更の要否は10.3★21)。

#### 処理内容

1. 通知は、画面表示時に次の元データから算出する。
   - 請求書の支払期限: 入金ステータスが「未入金」または「一部入金」(F-05)の請求書。期限の表示開始日以降、および超過後に通知する。
   - 見積書の有効期限: 請求書に変換されていない見積書(F-03、F-04)。
   - 案件の納期: ステータスが「完了」以外の案件(F-08)。
   - 手動登録した期限。
2. 通知は「期限が超過」「期限が近い(表示開始日数以内)」の2つの状態で表示し、超過を先頭に、期限日の近い順に並べる。
3. 元データが解消された場合(入金済み、案件完了、見積が変換済み、期限の削除等)、通知は自動で表示されなくなる。
4. 「確認済み」にした通知は通知一覧・ホーム画面から非表示とする。ただし、超過状態に変わった場合など、状態が進んだときの再表示の扱いは設計フェーズで確定する。
5. 毎年繰り返す期限は、期限日を過ぎて「確認済み」にした後、翌年の同じ月日を次の期限とする。
6. 同じ請求書等について、F-05の強調表示・件数サマリーと通知は併存するが、通知内での重複(同一の元データで複数の通知)は出さない。
7. 通知手段はアプリ内表示のみ。メール・OS通知・アプリ非起動時の通知は行わない。

#### 出力

- 通知一覧画面(種別・内容・期限日・状態)
- 期限の登録・編集・一覧画面
- ホーム画面(F-06)の通知エリア

#### 例外・エラー時の扱い

- 名称または期限日が未入力の場合は保存できず、エラーメッセージを表示する。
- 元データ(請求書等)の取得に失敗した場合は、その種類の通知のみエラー表示とし、他の種類の通知の表示には影響させない。
- 確定申告書類の作成や契約書の管理は行わない。期限の登録・通知のみである(要件定義書5.2)。

### F-10 レポート出力(イテレーション3・段階2)

出力対象・様式・会計ソフトの連携先は要件定義書10.3★23・★24の確認前であり、以下は仮置きである(確認後に確定)。

#### 目的

蓄積したデータと財務ダッシュボード(F-07)の集計内容をPDF/CSVで出力し、資料作成や会計ソフトへの取り込みに使えるようにする(要件定義書6.10)。

### F-11 経営管理(イテレーション3・段階3)

範囲は要件定義書10.3★17・★25の確認前である。以下は6.11の推奨案(案A+案B)を仮置きとした仕様であり、確認後に確定する。案C(振り返りメモ)は含めない。

#### 目的

EIAI TECが、月次の目標と実績を見比べ、また案件ごとの採算を確認して、事業の状況を経営の視点で振り返れるようにする(要件定義書6.11)。

#### 入力

- 目標の登録・編集(案A): 対象年(暦年。仮置き)、月ごとの売上目標、月ごとの経費予算。
- 案件別採算の表示条件(案B): なし(全案件を対象に表示。ステータスでの絞り込みは可)。

#### 処理内容

1. 目標と実績の対比(案A): 対象年の各月について、実績の売上・経費・損益を、F-07と同じ集計定義(発生主義)で算出し、目標との差額と達成率を表示する。損益の目標は「売上目標-経費予算」とする。目標が未登録の月は対比の対象外(実績のみ表示)とする。
2. 案件別採算(案B): 案件ごとに、紐付いた請求書の合計金額(売上)、紐付いた経費の合計金額(F-02。経費の案件紐付けは10.3★20の確認後に確定)、差額(採算)を表示する。集計期間は案件全体の累計(仮置き)。売上は請求書の発行日基準の発生主義に従う。
3. 案件なしの請求書・経費は案件別採算に含めず、「案件なし」として合計のみ別に表示する(仮置き)。
4. 取引先別の採算・取引先単位の管理は、Tier3の#8(顧客管理)と重なるため含めない。
5. 本機能は目標値の登録を除き、他機能のデータを書き換えない。

#### 出力

- 目標と実績の対比画面(月次の表・グラフ)
- 案件別採算一覧画面

#### 例外・エラー時の扱い

- 目標値が0以下または数値以外の場合は保存できず、エラーメッセージを表示する。
- 達成率の算出で目標が0の場合は、達成率を「-」と表示する。
- 参照元データの取得に失敗した場合は、該当する区画にエラー表示を行い、他の区画の表示には影響させない。

| 集計指標 | 算出方法 | 月への計上基準 | 参照データ |
|---|---|---|---|
| 月次売上 | 該当月に発行された請求書の合計金額を集計 | 請求書の発行日を基準に計上(発生主義) | 請求書(5.2) |
| 月次入金額 | 該当月の入金記録の入金額を集計 | 入金日を基準に計上(参考指標。損益の計上基準には用いない) | 入金記録(5.6) |
| 月次経費(勘定科目別) | 該当月の経費を、経費管理(F-02)の勘定科目区分別に金額集計 | 経費の発生日を基準に計上(発生主義) | 経費(5.5) |
| 月次損益(収支) | 月次売上-月次経費 | 売上は請求書の発行日、経費は経費の発生日を基準に計上する発生主義(要件定義書10.2★14で確定) | 請求書(5.2)、経費(5.5) |
| 月次見積件数・金額 | 該当月に作成された見積書の件数・合計金額を集計 | 見積書の発行日を基準に計上 | 見積書(5.4) |
| 見積成約率 | 見積→請求変換件数 ÷ 見積作成件数 | (期間内の件数比のため計上基準は適用外) | 見積書(5.4)、請求書(5.2「元見積書ID」) |

集計対象期間(直近12ヶ月)のうち、実績(データ)が存在しない月についても、上表のすべての指標を0円・0件として算出結果に含め、期間全体の推移が連続して確認できるようにする(要件定義書10.2★16で確定)。

| 納期 | 納品・完了の期限日(任意) |
| 概要メモ | 自由記述(任意) |

請求書(5.2)・見積書(5.4)・経費(5.5。仮置き)から案件IDで参照される(多対1)。

### 5.10 通知(イテレーション3・仮置き。要件定義書10.3★21)

## 6. 用語集(仕様固有)

| 用語 | 説明 |
|---|---|
| 税区分 | 品目・経費ごとの消費税の扱い(標準10%/非課税/不課税/対象外)を表す分類。軽減税率8%は、EIAI TECの事業で対象取引が発生しないため扱わない(要件定義書10.1★3)。 |
| 入金ステータス | 請求書に対する入金の進捗を表す区分(未入金/一部入金/入金済み)。 |
| 支払期限超過 | 請求書の支払期限を過ぎても入金ステータスが「未入金」または「一部入金」のままである状態。 |
| 変換元見積書 | F-04によって請求書が作成された際の、複製元となった見積書。 |
| 財務ダッシュボード | F-01〜F-05の既存データを集計し、売上・入金、経費、損益、見積の状況を月次で可視化する画面(F-07)。 |
| 損益(収支) | ある月の売上金額から経費金額を差し引いた金額。 |
| 計上基準(発生主義・現金主義) | 売上・経費を「いつの月の実績とみなすか」の考え方。本システムでは発生主義を採用し、売上は請求書の発行日、経費は経費の発生日を基準に該当する月へ計上する(要件定義書10.2★14で確定)。 |
| 見積成約率 | 見積作成件数のうち、見積→請求の自動変換(F-04)によって請求書へ変換された件数の割合。 |
| 案件 | 取引先から受けた仕事のまとまり。請求書・見積書を紐付けられる(F-08)。 |
| カンバン | 案件をステータスごとの列にカードとして並べる表示形式。 |
| 通知 | 期限が近い、または超過した項目を、アプリ内で知らせる表示(F-09)。 |
| 確認済み | 通知を確認したことを記録し、通知を非表示にする操作。 |
| 達成率 | 実績金額 ÷ 目標金額(F-11)。 |
| 採算 | 案件の売上から経費を差し引いた金額(F-11)。 |
