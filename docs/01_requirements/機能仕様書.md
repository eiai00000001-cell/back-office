## 4. 機能別詳細仕様

### F-01 請求書発行

#### 目的

EIAI TECが取引先への請求書を作成し、金額計算を誤りなく行った上でPDFとして出力できるようにする(要件定義書6.1)。

#### 入力

- 取引先(請求先): 取引先マスタ(5.1参照)から選択、または新規登録。
- 発行日、支払期限
- 請求書番号: 自動採番(手動編集は不可とする。採番ルールは「発行年+連番」とする)
- 品目明細(1件以上): 品目名、数量、単価、税区分(標準10%/非課税/不課税から選択。軽減税率8%は扱わない。要件定義書10章★3)
- 備考(任意)
- 発行者情報(EIAI TECの氏名・屋号・住所・連絡先、適格請求書発行事業者登録番号): システム設定として別途登録し、請求書作成時は登録済み情報を参照する想定。登録番号欄はレイアウト上用意するが、記載は必須としない(インボイス制度への対応方針自体は未定。要件定義書10章★1)

#### 処理内容

1. 品目明細ごとに「数量×単価」で金額を算出する。
2. 税区分ごとに小計を集計し、税区分ごとの消費税額を計算する(消費税額の端数処理は切り捨てとする。要件定義書10章★2)。
3. 小計・消費税額・合計金額を自動計算し、画面に表示する。
4. 保存時に請求書番号を自動採番する。
5. 請求書データをもとにPDFを生成し、画面から保存・印刷できるようにする。
6. インボイス制度に対応するレイアウト(登録番号欄、税率ごとの区分記載、適用税率、税率ごとの消費税額)を帳票フォーマットに含める。登録番号欄は記載必須項目とはしない(要件定義書10章★1)。

#### 出力

- 請求書一覧画面(請求書番号・取引先・発行日・支払期限・合計金額・入金状況(F-05と連携)を表示)
- 請求書詳細画面
- 請求書PDF

#### 例外・エラー時の扱い

- 品目明細が0件の場合は保存できず、エラーメッセージを表示する。
- 数量・単価に0以下または数値以外が入力された場合は保存できず、エラーメッセージを表示する。
- 取引先が未選択の場合は保存できず、エラーメッセージを表示する。
- 発行済みの請求書番号は変更できない(再発行が必要な場合は新規作成とする)。

### F-02 経費管理

#### 目的

EIAI TECが日々発生する経費を記録し、勘定科目別・期間別に集計・確認できるようにする(要件定義書6.2)。

#### 入力

- 発生日
- 勘定科目: 下記の標準科目リスト(青色申告向け)から選択(要件定義書10章★4で確定)
  - 旅費交通費、通信費、消耗品費、水道光熱費、地代家賃、外注工賃、接待交際費、会議費、新聞図書費、支払手数料、租税公課、雑費、その他(自由入力)
- 金額
- 税区分(標準10%/非課税/不課税/対象外から選択。軽減税率8%は扱わない。要件定義書10章★3)
- 支払先(任意)
- 支払方法(現金・クレジットカード・銀行振込・その他から選択。この選択肢はEIAI TECへのヒアリング対象外の実装レベルの初期案であり、必要に応じて設計フェーズで見直してよい)
- メモ(任意)
- 領収書ファイル(画像・PDF、任意添付。初回スコープに正式に含む。要件定義書10章★5)

#### 処理内容

1. 入力内容をもとに経費データを保存する。
2. 経費一覧を発生日の新しい順に表示する。
3. 勘定科目・支払方法・期間による絞り込み検索ができる。
4. 勘定科目別・期間(月単位)別に金額を集計し、一覧表示できる。
5. 領収書ファイルが添付されている場合、一覧・詳細画面からファイルを確認できる。

#### 出力

- 経費一覧画面
- 勘定科目別・期間別集計結果画面

#### 例外・エラー時の扱い

- 金額が0以下または数値以外の場合は保存できず、エラーメッセージを表示する。
- 勘定科目・発生日が未入力の場合は保存できず、エラーメッセージを表示する。
- 対応していない形式のファイルが添付された場合はエラーメッセージを表示し、添付を受け付けない(対応形式は設計フェーズで確定)。

### F-03 見積書作成

#### 目的

EIAI TECが取引先への見積書を作成し、金額計算を誤りなく行った上でPDFとして出力できるようにする(要件定義書6.3)。

#### 入力

- 取引先(見積先): 取引先マスタ(5.1参照)から選択、または新規登録。
- 発行日、有効期限
- 見積書番号: 自動採番(発行年+連番とする)
- 品目明細(1件以上): 品目名、数量、単価、税区分
- 備考(任意)
- ステータス: 「作成中」「確定」の2区分とする(提出済み・承認・却下等の詳細なワークフローは持たない。要件定義書10章★7で確定)

#### 処理内容

1. F-01と同様のロジックで、品目明細から小計・税区分ごとの消費税額・合計金額を自動計算する。
2. 保存時に見積書番号を自動採番する。
3. 見積書データをもとにPDFを生成し、画面から保存・印刷できるようにする。

#### 出力

- 見積書一覧画面(見積書番号・取引先・発行日・有効期限・合計金額・ステータスを表示)
- 見積書詳細画面
- 見積書PDF

#### 例外・エラー時の扱い

- 品目明細が0件の場合、数量・単価が不正な値の場合、取引先未選択の場合は、F-01と同様に保存できずエラーメッセージを表示する。

---

### F-04 見積→請求の自動変換

#### 目的

確定済みの見積書の内容を請求書へ引き継ぎ、同じ内容の二重入力をなくす(要件定義書6.4)。

#### 入力

- 変換元とする見積書(見積書一覧・詳細画面から選択)

#### 処理内容

1. 選択した見積書の取引先情報・品目明細(品目名・数量・単価・税区分)を複製し、新規の請求書データを作成する。
2. 新規請求書には新たな請求書番号を自動採番する。
3. 発行日・支払期限は変換時点では未設定とし、ユーザーが入力・編集する。
4. 変換後の請求書は、通常の請求書編集画面(F-01)と同じ画面で内容を編集できる。
5. 変換元の見積書と変換後の請求書は、変換後は互いに独立したデータとして扱う(一方を編集しても他方には反映されない)。請求書データには変換元の見積書番号を参照情報として保持し、どの見積書から変換されたかを画面上で確認できるようにする。
6. 1件の見積書から変換できる請求書は1件とする(1対1。要件定義書10章★8で確定)。部分請求・分割請求への対応は本イテレーションでは扱わない。ただし将来イテレーションでの拡張要望を踏まえ、請求書側から見積書を一方向に参照する構造とし、見積書側に「1対1」を固定する制約は持たせない設計とする(要件定義書7章参照)。将来イテレーションで分割請求・部分請求(1見積書から複数請求書)への拡張を行う際の具体的なデータモデル変更は、当該イテレーションの設計フェーズで検討する。

#### 出力

- 変換によって新規作成された請求書(編集可能な状態の請求書詳細画面)

#### 例外・エラー時の扱い

- 見積書のステータスが「作成中」であっても変換は可能とする(要件定義書10章★7)。
- 変換元見積書がすでに他の請求書に変換済みの場合は、1対1の対応関係(要件定義書10章★8)を維持するため、再変換を不可とし、確認ダイアログを表示する。

### F-05 入金・売掛金管理

#### 目的

発行済みの請求書について入金状況を記録し、売掛金(未回収金額)と支払期限超過の状況を把握できるようにする(要件定義書6.5)。

#### 入力

- 対象請求書(請求書一覧・詳細画面から選択)
- 入金日、入金額、備考(任意)

#### 処理内容

1. 請求書ごとに、記録済みの入金額の合計と請求金額を比較し、入金ステータスを自動判定する。
   - 入金額合計が0円: 「未入金」
   - 入金額合計が請求金額未満: 「一部入金」
   - 入金額合計が請求金額以上: 「入金済み」
2. 支払期限を過ぎても「未入金」または「一部入金」のままの請求書を「支払期限超過」として判定する。
3. 請求書一覧・売掛金一覧画面において、「支払期限超過」の請求書を強調表示(色分け等)する。
4. ホーム画面(F-06)に、未入金件数・支払期限超過件数のサマリーを表示する。
5. アラートは画面表示によるものに限定し、メール送信・デスクトップ通知等のプッシュ型通知は行わない(要件定義書10章★6で確定)。

#### 出力

- 売掛金一覧画面(取引先・請求書番号・請求金額・入金済み金額・入金ステータス・支払期限超過有無を表示)
- 入金記録一覧(請求書ごと)

#### 例外・エラー時の扱い

- 入金額が0以下または数値以外の場合は保存できず、エラーメッセージを表示する。
- 入金額合計が請求金額を超過する入力を行った場合は、確認メッセージを表示した上で登録可否をユーザーに委ねる(過入金・一部返金等のケースを想定)。

### F-06 ホーム画面・共通UI

#### 目的

EIAI TECがシステム起動後にF-01〜F-05の各機能へ迷わず移動できるようにし、業務上把握しておきたい簡易な状況を一目で確認できるようにする(要件定義書6.6)。

#### 入力

- なし(表示専用画面)

#### 処理内容

1. F-01(請求書発行)・F-02(経費管理)・F-03(見積書作成)・F-05(入金・売掛金管理)への導線をメニューまたはカード形式で表示する。F-04(見積→請求の自動変換)は独立した導線ではなく、見積書詳細画面(F-03)からの操作導線として提供する。
2. 未入金件数、支払期限超過件数など、F-05から取得した簡易なサマリー情報を表示する。
3. 詳細な集計・グラフ表示は行わない(財務ダッシュボード相当の機能はTier2として対象外)。

#### 出力

- ホーム画面

#### 例外・エラー時の扱い

- サマリー情報の取得に失敗した場合は、該当箇所にエラー表示を行い、他の導線メニューの表示・操作には影響させない。

## 5. データ項目定義

各エンティティの主要な項目を示す。詳細な型・桁数・制約は設計フェーズ(architecture)で確定する。

### 5.1 取引先マスタ

| 項目 | 説明 |
|---|---|
| 取引先ID | 取引先を一意に識別するID |
| 名称 | 取引先の会社名・屋号等 |
| 郵便番号・住所 | 取引先の所在地 |
| 担当者名 | 取引先の担当者氏名(任意) |
| 連絡先 | 電話番号・メールアドレス等(任意) |

### 5.2 請求書

| 項目 | 説明 |
|---|---|
| 請求書ID | 請求書を一意に識別するID |
| 請求書番号 | 自動採番される請求書番号 |
| 取引先ID | 請求先の取引先を参照 |
| 発行日・支払期限 | 請求書発行日・入金期限 |
| 小計・消費税額・合計金額 | 税区分ごとの計算結果を含む |
| 元見積書ID | F-04で変換された場合の変換元見積書への参照(任意)。本イテレーションでは1件の見積書につき1件の請求書(1対1)のみを想定するが、将来の分割請求・部分請求への拡張時に手戻りを抑えるため、参照は請求書側から見積書側への一方向とし、見積書側には請求書との1対1を固定する制約を持たせない(要件定義書10章★8、7章参照) |
| 入金ステータス | 未入金/一部入金/入金済み(F-05で算出) |
| 備考 | 自由記述(任意) |

### 5.3 請求書明細

| 項目 | 説明 |
|---|---|
| 明細ID | 明細行を一意に識別するID |
| 請求書ID | 紐づく請求書への参照 |
| 品目名・数量・単価・税区分・金額 | 明細行の内容 |

### 5.4 見積書・見積書明細

- 請求書・請求書明細に準じた構成とし、支払期限の代わりに「有効期限」、入金ステータスの代わりに「ステータス(作成中/確定)」を持つ(要件定義書10章★7で確定)。

### 5.5 経費

| 項目 | 説明 |
|---|---|
| 経費ID | 経費記録を一意に識別するID |
| 発生日・勘定科目・金額・税区分 | 経費の基本情報 |
| 支払先・支払方法・メモ | 補足情報(任意) |
| 添付ファイルパス | 領収書ファイルの保存先参照(任意) |

### 5.6 入金記録

| 項目 | 説明 |
|---|---|
| 入金ID | 入金記録を一意に識別するID |
| 請求書ID | 紐づく請求書への参照 |
| 入金日・入金額・備考 | 入金内容 |

## 7. 要確認事項・未解決事項

初版(1.0)で暫定仕様としていた事項(要件定義書10章★1〜9に対応する箇所)は、2026-09-15実施のEIAI TEC本人へのヒアリングによりすべて確定した。確定内容・経緯は要件定義書10章を参照のこと(本書では重複記載しない)。各機能仕様の該当箇所には、対応する要件定義書10章の項番(★1〜9)を参照情報として付記している。

本改訂(1.1)時点で、本書に関連する未解決の要確認事項はない。なお、見積→請求変換(F-04)の対応関係については、今回は1対1のまま実装するが、将来イテレーションでの分割請求・部分請求への拡張要望があるため、データモデル設計上の配慮事項として4章・5章に記載している(要件定義書10章★8、7章参照)。これは未解決事項ではなく、今後の拡張に備えた設計方針の記録である。
