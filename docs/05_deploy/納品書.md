## 2. 納品概要

### 2.1 納品日

2026-09-16

### 2.2 納品の位置づけ

本書は、個人事業(EIAI TEC)向け事務管理システムのイテレーション1(初回開発)について、計画・要件定義・設計・実装・テストの全フェーズが完了したことを受け、EIAI TEC本人への納品物一式を取りまとめたものです。実装コード自体はすでにテスト済みであり、本フェーズでは新たな機能追加・コード修正は行っておりません。

### 2.3 納品成果物一覧

| 区分 | 内容 | 格納場所 |
|---|---|---|
| プログラム本体 | バックエンド(FastAPI)、フロントエンド(React) | `backend/`、`frontend/` |
| データベース | SQLiteファイル(初回起動時に自動作成) | `db/back_office.db` |
| 添付・生成ファイル領域 | 領収書添付ファイル、生成PDFの保存先 | `data/` |
| 起動・終了用アプリ | ダブルクリックで起動・終了できるmacOSアプリ | `dist/起動.app`、`dist/終了.app` |
| 設計・仕様書一式 | 計画書、要件定義書、機能仕様書、基本設計書、詳細設計書、画面モックアップ | `docs/00_overview/`〜`docs/02_architect/` |
| 品質関連資料 | レビュー結果報告書、テスト仕様書・テストケース・テスト結果報告書 | `docs/03_develop/`、`docs/04_test/` |
| 納品資料(本書一式) | 納品書、操作マニュアル | `docs/05_deploy/` |

### 2.4 データベースの状態について

納品にあたり、`db/back_office.db`は開発・テスト過程で作成された確認用データ(取引先・請求書・見積書・経費等のテストデータ)を削除し、まっさらな状態にしています。次回`起動.app`をダブルクリックした際、Alembic(データベースの初期設定を行う仕組み)により空のデータベースが自動的に再作成されることを、本納品書作成にあたり実機で再確認済みです(取引先0件、システム設定は初期値の空レコード1件の状態からスタートします)。

## 5. セットアップ手順

以下は、実際にこのMac上で動作を再確認した手順です。今回お渡しする一式は、すでにセットアップが完了した状態(プログラムの準備・データベースの初期設定・起動用アプリの作成まで完了)でお渡ししていますので、通常は「5.4 日常のご利用(セットアップ後)」だけご覧いただければ十分です。5.1〜5.3は、今後別のMacに移す場合や、環境を作り直す場合の参考情報として記載しています。

### 5.1 事前に必要なもの(初回のみ・再現確認済み)

- macOS(Windows非対応)
- Homebrew(Macのパッケージ管理ツール)経由で、帳票(PDF)作成に必要な部品を導入します。

```bash
brew install pango gdk-pixbuf libffi cairo
```

このMac上には、上記4つがすでに導入済みであることを確認しています(`cairo` 1.18.4、`gdk-pixbuf` 2.44.8、`libffi` 3.8.0、`pango` 1.58.2)。

### 5.2 プログラムの準備(初回のみ・再現確認済み)

```bash
cd back-office
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
cd backend
../backend/.venv/bin/alembic upgrade head     # データベース(db/back_office.db)を作成
```

本納品書の作成にあたり、`alembic upgrade head`を実際に再実行し、データベースファイル(`db/back_office.db`)が正しく作成され、取引先0件・システム設定1件(空の初期状態)というまっさらな状態になることを確認しています。

### 5.3 画面(フロントエンド)のビルド(初回のみ・再現確認済み)

```bash
cd frontend
npm install
npm run build          # backend/static に画面一式が出力される
```

このMac上にはすでにビルド済みの画面一式(`backend/static/`)が存在することを確認しています。

### 5.4 日常のご利用(セットアップ後)

日常のご利用では、ターミナル操作は一切不要です。詳しい操作手順は「操作マニュアル.md」をご覧ください。

1. `dist/起動.app`をダブルクリックすると、自動的にシステムが立ち上がり、既定のWebブラウザで画面が開きます。
2. ご利用が終わったら、`dist/終了.app`をダブルクリックしてください。ブラウザのタブを閉じるだけではシステムは終了しませんので、ご注意ください。

本納品書作成にあたり、バックエンドプログラムを実際に起動し、以下を確認済みです。

- `GET /api/health`(正常確認用の窓口)が正常応答すること
- トップページ(`http://127.0.0.1:8000/`)が正しく表示されること
- ホーム画面のサマリー情報取得(`GET /api/home/summary`)が正常に応答すること(未入金0件・支払期限超過0件という、まっさらな状態どおりの結果)

`起動.app`/`終了.app`そのもののダブルクリック起動については、テストフェーズにおいてmacOSの`open`コマンド(Finderのダブルクリックと同じ仕組みによる起動)を用いた実機確認が完了しています(テスト結果報告書TC-A01〜TC-A04、全件合格)。実際の手作業でのダブルクリック時に表示されうる初回警告(Gatekeeper)への対処法は、4章★1および操作マニュアル.md 2章をご参照ください。

### 5.5 テストの実行方法(開発者向け参考情報)

```bash
cd backend && .venv/bin/python -m pytest -q
cd frontend && npx vitest run
```

バックエンド127件・フロントエンド30件のテストが全件成功することを、実装・レビュー・テストの各フェーズで確認済みです(README.md 5章、テスト結果報告書参照)。
