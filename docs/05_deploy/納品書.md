### 2.2 納品の位置づけ

本書は、個人事業(EIAI TEC)向け事務管理システムについて、計画・要件定義・設計・実装・テストの各フェーズが完了した内容を取りまとめた、EIAI TEC様への納品物一式です。

- イテレーション1: 請求書発行・経費管理・見積書作成・見積→請求の自動変換・入金/売掛金管理・ホーム画面(F-01〜F-06)、取引先マスタ管理・システム設定・アプリ起動終了
- イテレーション2: 財務ダッシュボード(F-07)
- イテレーション3・段階1(本改訂): 案件・プロジェクト管理(F-08、画面SC-13〜15)。請求書・見積書・経費を案件に任意で紐付けられます。
- イテレーション3・段階2(本改訂): リマインダー/通知(F-09、画面SC-16・17)、レポート出力(F-10、画面SC-18)。ホーム画面(SC-01)には通知エリアと導線カードが加わっています。
- **段階3(経営管理 F-11、画面SC-19・20)は未着手のため、今回の納品対象に含まれません。** 詳細は3章末尾および4.4章をご覧ください。

段階1・2はいずれもテスト済みで、本フェーズ(納品)では新たな機能追加・コード修正は行っていません。

**重要(納品前の必須作業)**: 現在の画面一式(`backend/static/`)は、段階1までの内容を含む古いビルドのままで、**段階2の画面(通知一覧・期限の登録・レポート出力、ホーム画面の通知エリア)を含んでいません。** 段階2の機能を`起動.app`でお使いいただくには、5.3章の「フロントエンドの再ビルド」を必ず実施してください(未実施のまま起動しても、エラーにはなりませんが、新しい画面は表示されません)。

## 5. セットアップ・更新手順

今回お渡しする一式は、すでにプログラムの準備・起動用アプリの作成まで完了した状態です。ただし、**「5.3 フロントエンドの再ビルド」は納品前(または更新前)に必ず実施する必要があります。** 5.1〜5.2は、別のMacに移す場合や環境を作り直す場合の参考情報です。

なお、以下のうち、5.3のビルドは今回の納品作業では実行していません(既存の画面ファイルの置き換えを伴うため、実施にはご本人のご許可が必要です)。5.5の自動更新も、実データベースに触れない条件のため、実データベースでは実行していません(コピーを使ったテストでの確認結果を記載しています)。

### 5.1 事前に必要なもの(初回のみ・再現確認済み)

- macOS(Windows非対応)
- Homebrew経由で、帳票(PDF)作成に必要な部品を導入します。

```bash
brew install pango gdk-pixbuf libffi cairo
```

### 5.2 プログラムの準備(初回のみ・再現確認済み)

```bash
cd back-office
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
```

データベースの作成・更新は、`起動.app`の起動時に自動で行われます(5.5章)。手動で行う場合は次のとおりです。

```bash
cd backend
../backend/.venv/bin/alembic upgrade head
```

### 5.3 フロントエンドの再ビルド(必須手順)

**目的**: 画面一式(`backend/static/`)を、段階2の画面(SC-16〜18、ホーム画面の通知エリア)を含む最新の内容に更新します。現在の`backend/static/`は段階1までの内容で、レポート出力などの文言を含んでいません(テスト結果報告書★18)。

```bash
cd back-office/frontend
npm install        # 必要な部品の導入(段階1で案件カンバン用ライブラリが追加されています)
npm run build      # 型の検査(tsc -b)と画面のビルド(vite build)を続けて実行します
```

- **出力先**: `back-office/backend/static/`(`frontend/vite.config.ts`の`outDir: '../backend/static'`)。
- **影響範囲**: このビルドは出力先を**いったん空にしてから**新しい内容を書き出します(`emptyOutDir: true`)。現在の`backend/static/`内の`index.html`・`favicon.svg`・`icons.svg`・`assets/`(現在は`index-CDpmzU8z.js`という名前の1ファイル)が削除され、新しい名前(ファイル名の末尾のハッシュが変わります)のファイルに置き換わります。`backend/static/`は、バージョン管理の対象外(`.gitignore`)で、ビルドで何度でも再生成できるファイルですが、削除を伴うため、実行前にご本人の許可を得てください。これ以外のフォルダ(`db/`、`data/`、`backend/app/`など)には影響しません。
- **ビルド後の確認**: `終了.app`→`起動.app`の順に操作して起動し直し(すでに起動中の場合)、ホーム画面に「通知」エリアと「通知・期限」「レポート出力」のカードが表示されることを確認してください。
- 補足: ビルド時に「画面の部品が大きい」という警告が表示されますが、動作には問題ありません(4章★17)。`npm run build`は`tsc -b`で型の不整合があると途中で止まります。止まった場合は開発担当へご連絡ください。ビルドが途中で失敗した場合、`backend/static/`が空、または不完全な状態になる可能性があります。その場合は、原因を解消して再度`npm run build`を実行してください。
- テスト担当者は、実際の`backend/static/`は変更せず、別の場所へ出力する形(`vite build --outDir`)で、ビルドが成功することと、画面の動作を確認済みです。

### 5.4 日常のご利用(セットアップ後)

日常のご利用では、ターミナル操作は一切不要です。詳しい操作手順は「操作マニュアル.md」をご覧ください。

1. `dist/起動.app`をダブルクリックすると、自動的にデータベースが最新に更新され、システムが立ち上がり、既定のWebブラウザで画面が開きます。
2. ご利用が終わったら、`dist/終了.app`をダブルクリックしてください。ブラウザのタブを閉じるだけではシステムは終了しません。

### 5.5 データベースの自動更新(マイグレーション)と初回起動後の確認

段階1・2では、データベースに新しい表(案件、通知の確認済み記録、登録した期限)や項目(請求書・見積書・経費の案件欄)が加わりました。この更新は、**`起動.app`の起動時に自動で適用されます。手動の操作は不要です。**

**自動更新の動作(テスト済み。使い捨て環境・コピーでの確認)**

- すでに最新なら何もしません。
- 更新が必要な場合は、更新の前に、データベースを`db/back_office.db.before-<更新後のリビジョン>`という名前のファイルへ**自動でコピー(退避)**します。今回の更新後のリビジョンは`c4d8e2f6a715`なので、`db/back_office.db.before-c4d8e2f6a715`ができます。同じ名前のファイルがすでにある場合は上書きしません。
- 現在の実データベースは、段階1未適用の状態(リビジョン`2e1e85c3b7cc`)と想定されます。段階1・2の更新が続けて適用されます(リビジョン`a1c3f5e7b901`→`c4d8e2f6a715`)。既存のデータ(件数・金額)は変わらないことを、コピーを使ったテストで確認しています。
- データベースが存在しない場合は、新しく作成して最新の状態にします(退避コピーは作られません)。
- 二重に起動しても、同時に更新が走らないよう排他制御されます。

**初回起動後の確認方法**

1. `db/`フォルダに`back_office.db.before-c4d8e2f6a715`という退避コピーができていること(Finderで確認できます)。
2. 次のコマンドで、現在の版が`c4d8e2f6a715`になっていること。

```bash
cd back-office/backend
.venv/bin/alembic current          # c4d8e2f6a715 (head) と表示されれば最新です
.venv/bin/python -m app.migrate    # 「マイグレーションは適用済みです」と表示されれば正常です
```

3. ホーム画面が表示され、これまでの請求書・見積書・経費・入金が残っていること。

**更新に失敗した場合**

- 日本語のダイアログに、失敗の理由(1行)と、`backend/logs/uvicorn.log`の案内が表示され、システムは起動しません。データベースの構造が想定と違う場合は、何も変更せずに停止し、その旨が案内されます。詳しい内容はログに記録されます。
- **退避コピーからの復元手順**(データを更新前の状態へ戻す方法)
  1. `終了.app`でシステムを終了する(起動していない場合は不要)。
  2. `db/back_office.db`を別の場所へ、念のためコピーして保管する。
  3. 退避コピー(`db/back_office.db.before-c4d8e2f6a715`)を`db/back_office.db`の名前でコピーして、置き換える。**(元の退避コピーは残してください)**
  4. 開発担当へ、ログ(`backend/logs/uvicorn.log`)の内容とあわせてご連絡ください。原因が解消するまで、`起動.app`を続けて起動しないでください(同じ失敗を繰り返します)。
- 更新前の状態へ戻すための「ダウングレード」機能はありません。復旧は退避コピーからの復元で行います。
- 更新の前に、念のため`db`フォルダ全体と`data`フォルダを別の場所へコピーしておくことをおすすめします。

**`起動.app`を使わず、開発用に直接起動する場合(参考)**

`uvicorn`を直接起動する場合は、自動更新が行われないため、**必ず先に**次を実行してください。実行しないとテーブルがなく、通知・案件などの機能がエラーになります。

```bash
cd back-office/backend
.venv/bin/python -m app.migrate          # または .venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### 5.6 テストの実行方法(開発者向け参考情報)

```bash
cd backend && .venv/bin/python -m pytest -q
cd frontend && npx vitest run
```

バックエンド417件・フロントエンド100件のテストが全件成功することを、実装・テストの各フェーズで確認済みです(README.md 5章、テスト結果報告書TC-RG16)。テストは実データベースを使わない仕組みになっています。
