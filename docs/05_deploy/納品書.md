### 2.2 納品の位置づけ

本書は、個人事業(EIAI TEC)向け事務管理システムについて、計画・要件定義・設計・実装・テストの全フェーズが完了した内容を取りまとめた、EIAI TEC本人への納品物一式です。

- イテレーション1(2026-09-16納品): 請求書発行(F-01)・経費管理(F-02)・見積書作成(F-03)・見積→請求の自動変換(F-04)・入金/売掛金管理(F-05)・ホーム画面/共通UI(F-06)、および取引先マスタ管理・システム設定(発行者情報)・アプリ起動終了の共通機能を対象としました。

実装コード自体はいずれもすでにテスト済みであり、本フェーズ(納品)では新たな機能追加・コード修正は行っておりません。

### 2.4 データベースの状態について

イテレーション1納品時点(2026-09-16)では、`db/back_office.db`は開発・テスト過程の確認用データを削除し、まっさらな状態(取引先0件等)でお渡ししていました。

**イテレーション2納品にあたっての変更点**: 今回は、財務ダッシュボード機能(F-07)のテスト過程で作成した検証用の取引先データが1件、削除されないまま残っています。本納品書作成にあたり、実際に`db/back_office.db`の中身を確認したところ、以下の状態でした。

- 取引先(`clients`テーブル): 1件(「tester検証用取引先(F-07)」という名称の、テスト目的のダミーデータ)
- 請求書・見積書・経費・入金記録: いずれも0件
- システム設定(`company_profile`): 初期値の空レコード1件

これは、現在のシステムには取引先を削除する機能が実装されておらず(4章の既知の制限事項参照)、テスト担当者が動作確認のために作成した1件のみを削除できなかったことによるものです。実害はありませんが(関連する請求書・見積書等はすべて削除済み)、実運用を開始される前に、SC-10(取引先マスタ管理画面)からこの取引先の名称を実際にお使いになる取引先名に書き換えて再利用いただくか、そのまま放置しても差し支えございません。詳しくは4章の表(★8)をご覧ください。

なお、`db/back_office.db`を削除したうえで`起動.app`を起動し直すと、Alembic(データベースの初期設定を行う仕組み)により空のデータベースが自動的に再作成されることも確認済みです(取引先0件の状態から始めたい場合はこの方法もご利用いただけます)。

## 5. セットアップ手順

以下は、実際にこのMac上で動作を再確認した手順です。今回お渡しする一式は、すでにセットアップが完了した状態(プログラムの準備・データベースの初期設定・起動用アプリの作成まで完了)でお渡ししていますので、通常は「5.4 日常のご利用(セットアップ後)」だけご覧いただければ十分です。5.1〜5.3は、今後別のMacに移す場合や、環境を作り直す場合の参考情報として記載しています。

### 5.1 事前に必要なもの(初回のみ・再現確認済み)

- macOS(Windows非対応)
- Homebrew(Macのパッケージ管理ツール)経由で、帳票(PDF)作成に必要な部品を導入します。

```bash
brew install pango gdk-pixbuf libffi cairo
```

このMac上には、上記4つがすでに導入済みであることを確認しています(`cairo` 1.18.4、`gdk-pixbuf` 2.44.8、`libffi` 3.8.0、`pango` 1.58.2)。

### 5.2 プログラムの準備(初回のみ・再現確認済み)

```bash
cd back-office
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
cd backend
../backend/.venv/bin/alembic upgrade head     # データベース(db/back_office.db)を作成・更新
```

### 5.4 日常のご利用(セットアップ後)
